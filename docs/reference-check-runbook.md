# Verificación reproducible del paquete de referencia

`python tools/check_reference_package.py` comprueba inventario SHA-256/tamaños, originales, R02, matriz, plantilla vacía y guardas de la fase actual. Ejecuta las 21 referencias registradas en `reference-runner-map.json` dentro de una copia temporal; no reescribe los resultados ni los originales de la carpeta verificada. Las bibliotecas necesarias están fijadas en `requirements-reference.txt`.

En un entorno Python 3.11 preparado con esas dependencias, ejecutar desde la raíz del repositorio. Si se suministra PYTHONPATH para bibliotecas locales, debe contener rutas absolutas porque las referencias se ejecutan en otra carpeta. Los paquetes se instalan en el entorno elegido; el verificador no instala nada, no se conecta a servicios, no interpreta fórmulas de Excel y no publica resultados financieros.

El workflow `.github/workflows/model-reference-checks.yml` solicita ejecución en push a main, pull request o ejecución manual. Usa permiso de contenido de lectura y checkout sin persistir credenciales. No configura deploy, base de datos, sincronización del VPS o autorización de PASS/FAIL. Acciones oficiales fijadas por commit: [checkout](https://github.com/actions/checkout/tree/11bd71901bbe5b1630ceea73d27597364c9af683) y [setup-python](https://github.com/actions/setup-python/tree/a26af69be951a213d495a4c3e4e4022e16d87065). La versión menor Python y la imagen de runner reciben actualizaciones; fijar estas acciones/dependencias no garantiza un entorno idéntico bit a bit.

Las guardas son específicas de esta fase: entradas/criterios reales vacíos, decisiones técnicas/financieras sin completar, módulos abiertos, R02 conservado y producción deshabilitada. Cuando exista una autorización nueva y evidencia aplicable, se revisarán las guardas de forma expresa. Que el control pase no acredita aprobación experta ni autoriza completar una elección pendiente.

El manifiesto se actualiza sólo al preparar un hito con inventario revisado. Un archivo cambiado, ausente o no listado hace fallar la comprobación. Los reportes/fixtures sintéticos se regeneran en la copia y se comprueban sus resultados/cantidades declaradas; no se exigen bytes idénticos de esos reportes entre plataformas. Las fuentes y los demás registros se mantienen intactos. El inventario detecta alteraciones respecto del manifiesto suministrado; no autentica a su autor ni detecta una falsificación coordinada de archivos y manifiesto.

El resultado local del verificador se conserva fuera del paquete. Un workflow guardado en GitHub no prueba que haya corrido allí: la evidencia de ejecución remota y las posibles restricciones de GitHub Actions se consultan por separado. No se declara CI remoto exitoso a partir de una ejecución en el VPS.
